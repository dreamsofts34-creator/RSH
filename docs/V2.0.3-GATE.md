```sh
cargo run -p rsh-rig -- --gate [--out DIR]   # 32 rig checks
```

clippy (`-D warnings`). It is **not** run by default: the full suite is
the gate coordinator's step and, per user order, runs only at phase
gates, not on every small fix.

## Round 1 (2026-11-17, `run-gate.sh --full`) — 6/8, two real failures

Logs: `/tmp/gate-run-2026-11-17-135257`.

| Step | Result |
|---|---|
| fmt / clippy-gate / rig-tests / build-lifecycle / ui-gate / clippy-workspace | PASS |
| rig-gate | **FAIL** — `gate-tray-persistence-source` |
| test-workspace | **FAIL** — `ui_lifecycle::tests::second_instance_forwards_and_first_claims` |

Both were diagnosed, not waived:

1. **Stale rig check (not a product bug):** `gate-tray-persistence-source`
   still audited for `should_dismiss_popup()`, which F9 replaced with the
   `PopupDismissPoll` state machine (commit `c58383f`). Rewrote the check
   to audit the state machine: 500 ms grace, never dismiss while
   foreground, dismiss only on sustained foreground loss or 3
   consecutive polls away from baseline, timer's single `hide()` behind
   the poll tick gate.
2. **Test-env bug (not product code):** the UI test spawned its fake
   process via `sh -c "exec -a rsh-ui sleep 30"`; `/bin/sh` on this box
   is dash, which has no `exec -a` — the fake died instantly and the pid
   was reclaimed as First. Fixed all three `exec -a` sites
   (`ui_lifecycle`, `single_instance`, `tray_geometry`) to spawn `sleep`
   directly with argv[0] via `CommandExt::arg0` (no shell involved).

Fixes committed as `bf8cee1` (plus gate-prep clippy fix `14699c0`:
`write_pid_file` dead on Linux → `#[cfg(any(test, windows))]`,
`matches!(…, Ok(_))` → `.is_ok()` — both pre-existing warnings the
`-D warnings` gate caught). Affected tests after the fix: UI
`ui_lifecycle` 4/4, daemon `single_instance` 8/8, `tray_geometry` 2/2,
rig 21/21, fmt clean.

## What the gate does NOT prove (honest list — Linux cannot prove these)

- **Windows named-pipe loop (R1):** the rig is Linux; the log file
  (`rsh-20261116_4_cj51.log`: 44 daemon starts, 1199× pipe create
  failed, 39 tray icons, 39 FATALs) IS the reproduction evidence. The
  F18 Windows CI job (`windows-pipe-loop`, real daemon + 12 s held pipe
  client) is review-validated only — its first CI run (on the merge to
  main) is the live proof.
- **Tray popup 5 s persistence + click-away on real Windows foreground,
  tray icon count / ghosting on Explorer, UAC prompt count, smart-
  installer update branches** — need the user PC (F19 protocol in
  `docs/V2.0.3-TRAY-ACCEPTANCE.md` is the test).
- **F27 Xvfb SIGSEGV:** closing during the reconnect seed fetch still
  segfaults under Xvfb — gdb proves the fault is in the llvmpipe render
  thread (no app frame on the crashing stack); the identical repro with
  `SLINT_BACKEND=software` survives and exits 0. App-code guards are in
  place; real-Windows proof needs the user PC. No deferred-hide was
  added (it would make X-click feel sluggish on the user's PC for an
  Xvfb-only artifact).
- **Frame-budget tick p99** is NOT directly measured (no in-process tick
  log exists; input-ack + liveness + exit latency are the external
  proxies). The check also PASSES on the pre-fix binary — it is a
  post-fix regression net, not a freeze discriminator; the freeze is
  proven by code analysis (F5/F6 job migration + tests) and the user-PC
  hang reports.
- **F20-C1:** UI single-instance pipe listener (Windows-only) retries a
  failed pipe create forever at fixed 1 s — needs a backoff ramp, but
  cannot be compile-checked or tested on Linux; left for the
  Windows-only pass (bounded consequence: one thread + log spam).
- **F20-C2:** watchdog fix real-board proof — healthy session stays
  `Active` with zero "heartbeat watchdog fired" lines; a board that
  authenticates but never streams latches `Error(WatchdogStall)`. Needs
  user PC + board, after v2.0.3 is stable.
- **F23 wizard re-offer on update install:** marker logic is proven on
  Linux; it assumes the installer does not wipe `%AppData%\RSH\setup-done`
  (unverified) and that v2.0.3 shows the wizard once for legacy markers.
  Needs the user PC.
- **F21 UDP holder proof:** closing/uninstalling the old `RSH.exe`
  frees UDP 4211 — needs the user PC (holder confirmed by elimination
  from the log only).
- **F13/F14 DEFERRED** (pairing/Wi-Fi path) — revisit when board work
  resumes, on user order. Board pairing / WebOTA test happens only
  after v2.0.3 is stable, on user order.
