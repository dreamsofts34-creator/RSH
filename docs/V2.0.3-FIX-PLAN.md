## Root causes (diagnosed 2026-11-17, code-verified; 5 diagnosis workers)

- **R1 — Daemon deterministic self-kill (P0, the loop killer):** Windows `serve_ipc` calls
  `ServerOptions::new().first_pipe_instance(true).create(IPC_PIPE_NAME)` on EVERY loop iteration
  (`crates/rsh-daemon/src/main.rs:608-640`). After the UI connects, pipe instance #1 stays alive, so the
  2nd create fails `PermissionDenied`; 5 consecutive failures → `IpcBindFailed` + `exit(1)` (~4–5 s after
  UI connects). Introduced by v2.0.2 M8 "5 attempts then fatal". Unix path binds once — Linux gate never
  executes the Windows loop. (Daemon worker)
- **R2 — Unbounded respawn (P0):** UI health monitor spawns the daemon every ~11 s forever when it dies
  (no backoff, no cap, no fatal-file check, no spawn-in-flight guard); Reconnect is a second concurrent
  spawner. Each spawn = new daemon = new tray icon. (UI worker)
- **R3 — A9 incomplete: UI-thread blocking (P0, the freeze):** `reconnect_to_live` runs ~35 sequential
  blocking IPC calls on the UI thread (up to ~17 s frozen on flap); frame-timer 5 s syncs 5–7 calls;
  slider flushes up to ~10 calls; many Slint-callback handlers still `block_on` (profiles, bindings,
  capture, tuning, close handler). `mark_dead` never drops the dead `IpcApi` (zombie poller spins forever).
  (UI worker)
- **R4 — Tray popup auto-hide, two mechanisms (P0):** (A) popup dies with its daemon — churn kills it,
  looks like auto-hide ~1 s; (B) transient foreground baseline: `foreground_at_show` sampled during the
  tray-click transition, Windows settles back after the 500 ms grace → poll rule (d) dismisses at ~0.6–1 s.
  Plus `was_foreground` trap, activation race (HWND not yet created), double FGW reads per tick,
  double-click toggle, zero popup logging. CP2 (d092500) fixed the static-foreground case only.
  (Tray worker)
- **R5 — Ghost tray icons (P0):** tray created once per daemon lifetime, `mem::forget`-leaked, NO
  `NIM_DELETE` anywhere; dead daemons leave ghosts until hover. Slint registers a zeroed GUID, so every
  respawn is a brand-new icon to Windows (user promotion never sticks). (Daemon + tray workers)
- **R6 — Notification spam (P1):** `NotificationCenter::push` unconditional (no dedupe key/cooldown, cap 50);
  daemon `PairingNeeded` re-fires on clear→refail (watchdog rebuild clears the typed error); one
  dead/back pair per flap. (Notifications worker)
- **R7 — Rejoin stall (P1):** `rejoin_wifi` runs 2 sequential blocking `netsh` calls inline on the
  manager-loop tokio task, no timeout; failure log-only. (Notifications worker)
- **R8 — Single-instance holes (P1):** Windows mutex airtight, but liveness is ping-only (no pid) — slow
  first-daemon startup (>1.5–2 s) yields a false `DaemonHung` fatal that overwrites the real status.
  (Daemon worker)
- **R9 — Detached spawn missing (P1):** UI→daemon and daemon→UI `Command::spawn` inherit stdio, no
  `DETACHED_PROCESS`/`CREATE_NEW_PROCESS_GROUP` — same bug class as the NSIS `Exec` hang fixed in b8b9fd4.
  (UI worker)
- **R10 — Silent panics (P1):** `install_panic_hook` is never called by the daemon — a panic leaves no log.
  (Daemon worker)
- **R11 — Gate hole (P0):** the gate never launches a real daemon/UI process; lifecycle checks are source
  audits or single-call probes. All four user-PC failures are lifecycle/time-series properties no check
  measures. (Rig worker)
