## How to run

```sh
# Full gate (fmt + gate clippy + rig tests + rig gate + UI gate):
tools/gate-checks/run-gate.sh [--out DIR]

# ...plus the full workspace suite (the gate coordinator's step):
tools/gate-checks/run-gate.sh --full
```

Individual pieces:

```sh
cargo run -p rsh-rig -- --gate [--out DIR]   # 22 rig checks
cargo run -p rsh-gate-ui                     # 6 headless UI checks
cargo test -p rsh-rig                        # 21 rig unit tests
cargo clippy -p rsh-rig -p rsh-gate-ui --all-targets -- -D warnings
cargo fmt --all -- --check
```

`--full` runs `cargo test --workspace --exclude rsh-app` and workspace
clippy (`-D warnings`). It is **not** run by default: the full suite is
the gate coordinator's step and, per user order, runs only at phase
gates, not on every small fix.

## Open verification (user PC — NOT proven here)

Wizard real click-through, tray 5 s persistence + click-away, X-close
instant reopen <1 s, hover repaint, real-board pairing, UAC prompt
count, WebOTA board flash, smart-installer update/reinstall/downgrade
branches (CI smoke test installs the same version twice).

Two kinds of rig check exist, and each check's detail says which it is:

- **runtime** — executes the real code (backend switch, typed errors,
  IPC timeout, OTA self-checks, performance timings).
- **source audit** — reads the tree as text and asserts the fix is present
  in the code that ships (slider fill binding, tray auto-hide, X-close
  wiring, wizard reopen, hover/theme/overflow markers). The real visual
  proof for these stays the user-PC retest; the audit only proves the
  code says what the fix claims. Nothing here pretends a Linux run proves
  a Windows behaviour.

## Release fix — Windows-only compile failures (2026-11-17 ~13:10 PKT)

The first release run (44043543021) failed at `cargo clippy
--workspace --exclude rsh-app --all-targets` on `windows-latest`:
the v2.0.2 gate/UI code used Unix-only APIs that were never
compiled for Windows (the local gate is Linux-only). Root cause,
not a product bug — three crates, all fixed in one commit after
the gate:

- `tools/rsh-rig/src/gate_checks.rs` — `tokio::net::UnixListener`
  at 3 fake-peer sites → new `FakeListener` (Unix socket on Linux,
  named-pipe server at the fixed `IPC_PIPE_NAME` on Windows, same
  pattern as the daemon's `serve_ipc`); `into_split()` →
  `tokio::io::split`.
- `crates/rsh-ui/src/ui_lifecycle.rs` — `NamedPipeClient::connect`
  → `ClientOptions::open`; `NamedPipeServer::create` →
  `ServerOptions::create`; `Win32_Security` feature added (gates
  `CreateMutexW`); unused `data_dir` silenced on Windows.
- `crates/rsh-ui/src/ipc_api.rs` + `crates/rsh-ipc/src/client.rs`
  — Unix-only test helpers/imports (`CaptureStubApi`,
  `CountingApi`, `AtomicUsize`, `super::*`, `Instant`) cfg-gated
  `#[cfg(unix)]` to match the Unix-only tests that use them.

Re-verified locally after the fix: `cargo fmt` clean; workspace
clippy 0 warnings on Linux AND on Windows (`--target
x86_64-pc-windows-gnu` — the MSVC target cannot run on this Linux
machine, no `lib.exe`; the fixed errors are target-OS-level and
identical on both Windows targets); `rsh-ui` 52/0, `rsh-rig`
21/21, `rsh-ipc` 13/0; rig gate re-run 22/22 PASS. Tag `v2.0.2`
moved to the fix commit (v2.0.1 precedent); release re-triggered.
