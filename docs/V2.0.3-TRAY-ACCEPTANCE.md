# RSH v2.0.3 — Tray popup + icon acceptance protocol (F19)

User-facing check for the v2.0.3 tray work (F9 poll hardening, F10
popup logging). Run on the user's PC, **without the board connected**
— v2.0.3 acceptance is software stability only (fix plan, scope
note 2026-11-17 ~15:27 PKT). No commands to run, no logs to collect
by hand: just watch the tray and the popup, and note pass/fail per
step.

## What changed (plain words)

- The tray popup used to vanish ~1 s after opening, even when nobody
  clicked anything. That was the daemon misreading Windows settling
  back to the app you had open before the tray click as "you clicked
  away". The poll now waits for Windows to settle, and only closes
  the popup on a real, sustained click somewhere else.
- Every popup open/close is now written to the daemon log with the
  reason, so a popup that closed itself and a popup that died with
  its daemon can finally be told apart.

## Protocol

Do the steps in order. The daemon must be running throughout (the
RSH tray icon is visible).

### (i) Popup stays open untouched — 5 s

1. Left-click the RSH tray icon. The popup opens.
2. Do not touch mouse or keyboard for 5 s.
3. **Pass:** the popup is still open after 5 s.

### (ii) Click-away closes it — within ~1 s

1. Open the popup (left-click the tray icon).
2. Wait ~2 s (let Windows settle — a click inside the first ~1 s is
   deliberately ignored, see "Known limits" below).
3. Click the desktop or another window.
4. **Pass:** the popup closes within ~1 s of that click.

### (iii) Double-click keeps it open

1. Double-click the RSH tray icon (two quick clicks).
2. **Pass:** the popup opens and stays open — it must not flash open
   and instantly close again.

### (iv) No new tray icon, daemon alive — 10 s

1. Open the popup and leave it open for 10 s, untouched.
2. **Pass:** the popup is still open AND no second RSH tray icon
   appeared (still exactly one icon). A new icon would mean the
   daemon died and respawned — the restart loop, not the popup.

### (v) Icon stays visible out of the overflow

1. If the RSH icon sits inside the `^` overflow flyout, drag it out
   onto the visible taskbar.
2. Restart the daemon (Quit RSH from the tray menu, then start RSH
   again) and wait for the tray icon to come back.
3. **Pass:** the icon is still in the visible taskbar area, not back
   inside `^`.

## If a step fails — what to note

- Which step, and what you saw instead (popup closed on its own?
  second icon? icon back in `^`?).
- Roughly how long after opening the popup closed (immediately,
  ~1 s, later?).
- The daemon log (`%AppData%\RSH\logs\rsh-*.log`, all dates — the PC
  clock is unreliable) now has one line per popup open/close; the
  support note is which line matches the failure:
  - `tray popup: shown pid=… foreground_at_show=…` — popup opened.
  - `tray popup: hidden reason=click-away …` — the poll decided you
    clicked away (note `elapsed_ms` and `baseline=`).
  - `tray popup: hidden reason=tray-click toggle …` — a second tray
    click closed it.
  - `tray popup: hidden reason=close-button …` — the popup's own
    close button.
  - No `hidden` line at all, but the popup is gone and a new
    `tray popup: shown` line appears with a **different pid** — the
    daemon died and respawned (restart loop, not a popup bug).
  - `tray popup: activation not achieved within 1 s …` — the popup
    stayed visible but never became the foreground window; it should
    still stay open until a real click-away, so on its own this line
    is not a failure.

## The `^` overflow — honest limit

The app **cannot force its icon out of the overflow**. Windows
decides which icons are visible, per icon — and every time the
daemon restarts, Windows sees a brand-new icon (the tray backend
registers the icon with no stable identity, so a respawn is a new
icon to Windows and any promotion you made does not stick). That is
why fixing the restart churn matters more than any setting: once
the daemon stops dying and respawning, a promotion you make once
stays made.

To promote the icon yourself:

- **Windows 11:** Settings → Personalisation → Taskbar → "Other
  system tray icons" → turn **RSH** on.
- **Windows 10:** Settings → Personalisation → Taskbar → "Select
  which icons appear on the taskbar" → turn **RSH** on.
- Or drag the RSH icon out of the `^` flyout onto the taskbar.

## Known limits (not bugs — do not re-report)

- A click-away inside roughly the first second after opening the
  popup may not close it (the poll is still letting Windows settle,
  and treats an early click as settling). Wait ~2 s after opening,
  then click away — step (ii) is written that way.
- If the main RSH window was already the foreground window when you
  opened the popup, clicking back into that same window leaves the
  foreground unchanged, so the popup stays open. Close it with
  Escape, a tray click, or "Open RSH" in the popup.
- The popup never auto-closes when Windows cannot say which window
  is in front — it stays open rather than guessing.
